## 1. Message Attribution

### Symptom:
Opening the exam from the website, Safe Exam Browser (SEB) does not show the launch-code form; it displays an error modal: **"Configuration failed"** (or in English locale: *"The local client configuration has failed! Please consult the log files for more information. SEB will now shut down..."*). Earlier, a launch-code form appeared.

### Source Attribution:
- **Repo search**: Grepping the repository for `"Configuration failed"` returns zero user-facing HTML templates. The repository's error screens display `"The exam system isn't ready, tell your invigilator (Ref: <id>)"` (in `studentErrors.js`, `LoginPage.jsx`, and `SebPinEntryPage.jsx`).
- **SEB Windows Source search**:
  Cloned `https://github.com/SafeExamBrowser/seb-win-refactoring.git` and inspected `.resx` and `en.xml` language dictionaries:
  - **Class**: `SafeExamBrowser.Runtime.Operations.Session.ConfigurationOperation` (lines 287-289):
    ```csharp
    Logger.Error($"Client configuration failed with status '{status}'!");
    ShowMessageBox(TextKey.MessageBox_ClientConfigurationError, TextKey.MessageBox_ClientConfigurationErrorTitle, icon: MessageBoxIcon.Error);
    ```
  - **Resource Key**: `MessageBox_ClientConfigurationErrorTitle` = `"Configuration Error"`
  - **Resource String**: `MessageBox_ClientConfigurationError` = `"The local client configuration has failed! Please consult the log files for more information. SEB will now shut down..."`
- **Verdict**:
  **Native SEB Dialog**. The error originates entirely within the Safe Exam Browser runtime application on Windows during its initialization and process-lockdown phase, prior to rendering any web content or loading the Start URL.

## 5. Diagnostic Instruments Implemented

1. **Config Doctor (`scripts/seb/config-doctor.js`)**:
   - Replicates exact SEB 3.x `NetworkResourceLoader` behavior (sequential HEAD followed by GET).
   - Validates HTTP response headers (`Content-Type: application/seb`, `Content-Disposition`, `Cache-Control`).
   - Verifies Apple XML Property List formatting and decompressibility.
   - Actively checks for non-killable background Windows services (Win32 Session 0 crash prevention).
   - Computes canonical normalized XML SHA-256 and compares with expected database key.
2. **Correlation ID & Hop Tracking**:
   - Every launch creates a cryptographic 12-char correlation ID (derived from the SHA-256 hash of the launch token, never exposing the raw token).
   - Carried and recorded across all lifecycle hops: `LAUNCH_LINK_CREATED` -> `CONFIG_DOWNLOAD_REQUEST` -> `TOKEN_EXCHANGE` / `PIN_EXCHANGE` -> `EXAM_START_ATTEMPT`.
3. **Admin Launch Traces View**:
   - Accessible via `GET /api/v1/admin/seb/launch-traces` and embedded inside `AdminSebConfigPage.jsx`.
   - Displays real-time per-hop status badges (200 OK vs failure codes), duration, and diagnostic details.

## 6. Root Cause Fixes & Verification

1. **Windows Background Service Crash Prevention**:
   - `backend/src/modules/seb/sebConfigChecker.js`: `sanitizeProhibitedProcesses()` sanitizes plain XML configurations upon upload and dynamic download, ensuring services running in Session 0 (`UltraViewer_Service.exe`, etc.) are not marked with `<true/>`.
   - Regression test: `backend/tests/seb-service-sanitization.test.js` (Passing).
2. **Proxy Config Download Integrity**:
   - Regression integration test: `backend/tests/seb-proxy-config-download.test.js` (4/4 Passing).
3. **Non-Dead-End Error Resilience on Start Page**:
   - `frontend/src/pages/student/StudentExamStartPage.jsx`: When any error or header mismatch occurs, the page renders the 6-digit code entry form, reference ID (`Ref: #${refId}`), "Sign in with password instead" fallback button, and diagnostics link. The student is never stranded with only "Return to Dashboard".
   - E2E test: `e2e/seb-start-page-states.spec.ts` (covers valid token, invalid token, expired token, no token, and start page error resilience).
