## 4. Item 0d: SEB Configuration Key Algorithm Audit

### How `sebConfigChecker.js` Computes Key Today
```javascript
function normalizePlistXml(xmlStr) {
  let cleaned = xmlStr.replace(/<!--[\s\S]*?-->/g, '')
  cleaned = cleaned.replace(/>\s+</g, '><').trim()
  return cleaned
}
function computeConfigKeyFromXml(xmlStr) {
  const normalized = normalizePlistXml(xmlStr)
  return crypto.createHash('sha256').update(normalized, 'utf8').digest('hex').toLowerCase()
}
```
`sebConfigChecker.js` strips whitespace between XML tags and hashes the raw XML string.

### Official SEB Specification & C# Source Implementation
Audit of `SafeExamBrowser.Configuration/ConfigurationData/DataProcessor.cs` and `Json.cs` in the official SEB Windows source repository (`seb-win-refactoring`):
1. SEB does **NOT** hash the XML plist string directly.
2. SEB parses the configuration dictionary into an in-memory dictionary.
3. It orders all dictionary keys alphabetically using invariant string comparison (`dictionary.OrderBy(d => d.Key, StringComparer.InvariantCulture)`).
4. It excludes `originatorVersion` and empty sub-dictionaries.
5. It serializes the data structure to compact **JSON** (booleans lowercase `true`/`false`, ISO-8601 timestamps, invariant numbers, compact brackets without extra spaces).
6. It computes **SHA-256** over this canonical JSON stream and converts to lowercase hex.

### Golden Vector Comparison
* **Stored S3 File**: Plain XML plist (`seb/institution-config.seb`, SHA256: `e8239382...`)
* **Stored DB Key**: Ends in `a843`
* **Result**: `computed key equals stored key: no`
* The current `computeConfigKeyFromXml` is incorrect and produces hashes incompatible with SEB's official JSON-serialization hashing specification.

## 6. Item 0f: Root Causes

### Root Cause: Safe Exam Browser Entry Failure
The SEB entry failure occurred because token/PIN exchange endpoints (`/seb/exchange` and `/seb/exchange-pin`) strictly enforced the `X-SafeExamBrowser-ConfigKeyHash` header at authentication time instead of delegating enforcement to exam-content endpoints (`start`, `answers`, `submit`). When the student opened SEB using the downloaded starter configuration, SEB computed its header hash using the starter key (`4b04249c...`), which did not match the active database key (`...a843`) that had drifted from the stored file. The server rejected the exchange with `403 SEB_HEADER_MISMATCH`, and the frontend collapsed the error into the generic message `"The exam system isn't ready, tell your invigilator"`, while the Admin page misleadingly displayed `"Verified ✓"` because its verification status was tied to an unversioned 7-day-old test ping.

### Root Cause: AI Question Generation Weak Grounding & Silent Fallback
The AI question generation issues stem from three defects: first, a silent deterministic fallback (`generateFallbackQuestions`) that automatically substitutes canned mock questions whenever an API key is missing or an LLM call fails, masking infrastructure failures from faculty; second, crude document processing that extracts PDF text as an unpaginated blob and truncates it at 15,000 characters without per-page tracking, word-count validation, or multi-chunk distribution; and third, the absence of server-side excerpt verification to prove that questions and answers are strictly grounded in verbatim citations from the uploaded source text.
