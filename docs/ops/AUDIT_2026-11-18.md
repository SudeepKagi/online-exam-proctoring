### 1.4 Answers to Critical Security Review Inquiries
1. **Can a request carrying a header computed with the starter key pass the gate?**
   - **YES**. Because `candidateKeys.add(STARTER_CONFIG_KEY.toLowerCase())` is checked unconditionally in `inspectSebRequest`, any client sending a hash computed with `STARTER_CONFIG_KEY` will pass the middleware gate even if the institution or exam is configured with a distinct, custom security key.
2. **Can a normal Chrome session redeem a launch token and then pass gated endpoints?**
   - **YES**. In `backend/src/modules/seb/seb.controller.js` line 604 (`exchangePin`), the endpoint only checked a superficial regex `isSebAgent = /SEB|SafeExamBrowser/i.test(userAgent)` and did not require a cryptographic header match. Furthermore, when `SEB_MODE=log` or if a browser spoofed the User-Agent, `exchangePin` redeemed the token, issued cookies, and called `markUserSebVerified(user.id, record.examId)`. Subsequent calls to `/attempts/exams/:id/start` and answer saves bypassed header verification via `isUserSebVerified`.
3. **Is the repository public?**
   - **YES**. Verified via GitHub API (`gh repo view SudeepKagi/online-exam-proctoring --json isPrivate`):
     ```json
     {"isPrivate":false,"name":"online-exam-proctoring","owner":{"id":"U_kgDODOGY4w","login":"SudeepKagi"}}
     ```
   - Committing `STARTER_CONFIG_KEY` into `backend/src/middleware/seb.js` published a static bypass key to the public domain.

## 2. Root Cause Analysis of Key Mismatch

### 2.1 The Origin of `4b04...` vs `b379...`
1. **Host Modification**:
   - In a previous turn, `%APPDATA%\SafeExamBrowser\SebClientSettings.seb` on the engineer workstation was overwritten with the plain template `proctornet-starter.seb`.
   - When Safe Exam Browser 3.10 for Windows initializes, it loads `%APPDATA%\SafeExamBrowser\SebClientSettings.seb`.
   - The SHA-256 Configuration Key calculated by SEB from that specific client settings file was `4b04249c...`.
2. **Server-Stored Institution Configuration**:
   - The institution configuration uploaded to production S3 (`proctornet-starter.seb`) was opened in the official Safe Exam Browser Configuration Tool on Windows (`SEB 3.10.3`).
   - The SEB Configuration Tool computed the official Configuration Key as:
     `b3795424e489b41ccc146325fc06707fb91dd510b34495294d73224f70f7a843`
   - This exact key (`b3795424...`) was saved in the production database table `SystemSetting`.
3. **Flawed Key Calculation in `sebConfigChecker.js`**:
   - In `backend/src/modules/seb/sebConfigChecker.js:24–31`, `computeConfigKeyFromXml` attempted to calculate the key using a naive string normalization (`normalizePlistXml(xmlStr)`) and SHA-256 hash.
   - The SEB official specification does not compute Configuration Keys from raw XML text formatting; it serializes the settings dictionary according to Apple Binary Property List / canonical format.
   - This caused the Admin UI to flag a false warning: *"The pasted Configuration Key does not match the computed hash of this plain configuration file."*
4. **Conclusion on Previous Fix**:
   - The hardcoding of `STARTER_CONFIG_KEY = '4b04...'` into `backend/src/middleware/seb.js` masked an inconsistency created when the local workstation's `%APPDATA%` file was overwritten.
   - A real student downloading the server configuration from `https://proctornet.duckdns.org/api/v1/seb/config/<token>.seb` computes the configuration key of the server-stored file (`b379...`), NOT `4b04...`.
