# Phase 0 Investigation & Diagnosis Report

**Date:** 2026-11-16  
**System:** ProctorNet Enterprise Online Exam & Proctoring Platform  
**Target Environment:** Production (`i-0d242d962823f0a89`, AWS `ap-south-1`, domain `https://proctornet.duckdns.org`)  
**Investigator:** Release Engineer  

---

## 1. Executive Summary

A comprehensive, non-destructive audit of the live production environment and the codebase was conducted across four critical operational areas:
1. **Safe Exam Browser (SEB) "Not Configured" Defect:** Root-caused to an architectural discrepancy in `exam.wizard.service.js` where the wizard publish guard only checked per-exam and environment variables, completely omitting the institution DB setting.
2. **Violation Log Empty Display Issue:** Violations are correctly ingested and persisted to PostgreSQL (`proctoring_logs` count = 12 on live). The issue is presentation: the faculty exam management UI lacks a dedicated "Violations" tab and only surfaces incidents if faculty drill into individual student modal views.
3. **Face Verification Pre-Check:** Pre-exam face verification is non-blocking in the frontend client (`PreExamCheckPage.jsx` wrapped the API call in `.catch(() => {})` and unconditionally proceeded). Furthermore, the client passed payload keys mismatching backend controller expectations (`{ image, examId }` vs `{ liveFrameKey, attemptId }`).
4. **Camera Streaming & Periodic Capture Inventory:** Complete catalog of all continuous camera capture components, WebRTC hooks, heartbeat intervals, socket handlers, and retention policies.

## 2. Investigation Details

### a. SEB Configuration: Trace of All Code Paths & Live Evidence

#### Code Path Analysis:
1. **Admin Save Endpoint (`POST /api/v1/admin/seb/config`):**
   - Implemented in `backend/src/modules/admin/sebAdmin.controller.js:61-114`.
   - Validates `.seb` file magic bytes/XML header and checks 64-hex `configKey`.
   - Uploads file buffer to S3 as `seb/institution-config.seb`.
   - Saves record into `system_settings` table via `settingsService.saveSebConfig({ fileKey, configKey, uploadedAt, lastVerifiedAt })`.
2. **Admin Status Endpoint (`GET /api/v1/admin/seb/status`):**
   - Implemented in `backend/src/modules/admin/sebAdmin.controller.js:116-149`.
   - Queries `settingsService.getSebConfig()`. Returns `{ configured: true, uploadedAt, keyLast4, lastVerifiedAt }` if `configKey` exists.
   - Falls back to `process.env.SEB_CONFIG_KEY`.
   - Note: Does not verify whether the S3 object actually exists in the bucket.
3. **Exam Service SEB Settings (`getSebSettings(examId)`):**
   - Implemented in `backend/src/modules/exams/exams.service.js:206-226`.
   - Checks `exam.proctoringConfig.sebRequired`.
   - Resolution hierarchy: `perExamKey || institutionKey (from DB) || envKey`.
4. **Standard Publish Guard (`publishExam(id)`):**
   - Implemented in `backend/src/modules/exams/exams.service.js:238-260`.
   - Checks `exam.proctoringConfig.sebRequired`.
   - Checks `perExamKey`, `institutionKey` (from `settingsService.getSebConfig()`), and `envKey`. Correctly permits publish if institution key exists in DB.
5. **Publish Wizard Guard (`publishWizard(userId, data)`):**
   - Implemented in `backend/src/modules/exams/exam.wizard.service.js:192-206`.
   - **CRITICAL BUG LOCATED:**
     ```javascript
     if (sebRequired) {
       const perExamKey = data.sebConfigKey || pConfigInput.sebConfigKey
       const envKey = process.env.SEB_CONFIG_KEY
       const validPerExam = perExamKey && /^[0-9a-fA-F]{64}$/.test(String(perExamKey).trim())
       const validEnv = envKey && /^[0-9a-fA-F]{64}$/.test(String(envKey).trim())
       if (!validPerExam && !validEnv) {
         const err = new Error('Exam requires Safe Exam Browser but no valid Config Key is configured.')
         err.status = 400
         err.code = 'SEB_KEY_REQUIRED'
         throw err
       }
     }
     ```
     `publishWizard` **never queried `settingsService.getSebConfig()`**. When faculty published through the Exam Wizard without supplying an exam-specific key or having `SEB_CONFIG_KEY` in environment variables, it threw `SEB_KEY_REQUIRED` (400).
6. **Wizard UI Status Call:**
   - In `frontend/src/components/faculty/ExamWizardStepSecurity.jsx:80`, UI calls `GET /exams/seb-status`.
   - Backend routes `/exams/seb-status` to `examsOpsController.getInstitutionSebStatus` (`requireRole('FACULTY', 'ADMIN')`), delegating to `sebAdminController.getSebStatus`.
   - If user is not authenticated or fails role check, the frontend caught the error and defaulted to `{ configured: false }`.
7. **In-Process Cache & Negative Results:**
   - In `backend/src/middleware/seb.js:106-124`, `getCachedSebSettings` caches results in-memory with a 60-second TTL (`EXAM_SETTINGS_TTL_MS`).
   - If an exam was created before the key was resolved or misconfigured, subsequent calls within 60s served the negative/empty key result from memory.

### c. Pre-Check Face Verification: Current State & Drivers

1. **Is Pre-Check Blocking Today?**
   - **NO.** In `frontend/src/pages/student/PreExamCheckPage.jsx:157`:
     ```javascript
     await apiClient.post('/media/verify-face', { image: imageBase64, examId: id }).catch(() => {})
     if (isSebActive) {
       await handleLaunchExam()
     } else {
       setStep(2)
     }
     ```
     Any failure, rejection, or network drop was completely swallowed by `.catch(() => {})`, immediately proceeding to launch the exam or step 2.
2. **Driver Used:**
   - Implemented in `backend/src/modules/media/media.service.js:77-128`.
   - Uses AWS Rekognition `CompareFacesCommand` with `@aws-sdk/client-rekognition`.
   - If Rekognition fails or credentials are missing: falls back to mock PASS in non-production.
3. **Reference Photo Origin & Storage:**
   - The reference photo is queried from `User.referencePhotoKey` or `User.profileMetadata.facePhotoDataUrl`.
   - If no reference photo exists on the student profile, `media.service.js:63-70` treats the initial pre-check photo as the established baseline and returns `PASS` (`verified: true, decision: 'PASS'`).
   - S3 Storage: Reference photos are stored under `reference-photos/` or inline data URLs in `profileMetadata`.

### d. Camera Streaming & Periodic Capture Inventory

The codebase currently contains extensive continuous camera streaming and periodic capture mechanisms:

1. **WebRTC Hooks & Global References:**
   - `frontend/src/hooks/useCamera.js`: Acquires `navigator.mediaDevices.getUserMedia({ video: ... })`, stores active tracks, and manages device switching.
   - `frontend/src/hooks/useScreenProctoring.jsx`: Connects to `window.__proctorCameraStream` and maintains a hidden `<video>` element (`position:fixed;top:-9999px`) actively playing the camera stream throughout the entire exam arena duration.
2. **Periodic Cadence & Heartbeats:**
   - `useScreenProctoring.jsx:78-83`: Dispatches `HEARTBEAT_SNAPSHOT` every 25 seconds via `setInterval`.
   - `backend/src/infra/websocket/socketHandlers.js`: Supports `proctor:cadence` socket updates.
3. **Snapshot Pipeline:**
   - On every event (`TAB_SWITCH`, `FULLSCREEN_EXIT`, `WINDOW_BLUR`), `captureSnapshot()` in `useScreenProctoring.jsx` draws the hidden video to a hidden canvas, downscales to 640x480 JPEG (0.6 quality), converts to base64 DataURL, and posts to `/proctoring/events`.
4. **`CAMERA_DISCONNECTED` Detection:**
   - `useScreenProctoring.jsx:86-99`: Listens for `track.onended` on the camera video track. If triggered, sets `cameraLost = true` and posts `CAMERA_DISCONNECTED` violation with severity `CRITICAL`.
5. **Consent Text:**
   - In `PreExamCheckPage.jsx:106`:
     *"I understand and consent to identity verification snapshots and proctoring logs being captured and retained for this exam session."*
6. **Retention:**
   - Governed by `backend/src/jobs/retentionJob.js` and `backend/src/shared/evidencePolicy.js` (retention period `RETENTION_DAYS`, default 30 days).
