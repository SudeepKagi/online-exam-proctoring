# ADR E2E-AI-001: AI-Driven Exploratory Testing Framework Selection (Midscene.js vs TesterArmy e2e)

**Status:** Accepted  
**Date:** 2026-10-10  
**Authors:** ProctorNet Engineering & QA Architecture  
**Context:** Prompt 8 — Layer 2 AI "Human Tester" Evaluation  

---

## 1. Context & Problem Statement

ProctorNet employs a deterministic, zero-flakiness Playwright test suite (Layer 1, Journeys J1–J9) as the mandatory gate for merges (`ci-gate`) and AWS deployments. However, scripted assertion testing cannot effectively catch:
- Confusing or ambiguous user interface states
- Dead-end interaction paths where no interactive control is obvious to an anxious student
- Awkward screen layouts, text overlaps, or unreadable typography under dynamic responsive conditions
- Inconsistent domain copy or technical jargon leaks (e.g. raw exception codes or unabstracted service terms)

To address these exploratory UX concerns without compromising the strict determinism of the merge gate, Prompt 8 specifies a **two-layer testing architecture**:
1. **Layer 1 (Deterministic Merge Gate):** Scripted Playwright journeys asserting strict UI states, database invariants, console cleanliness, and HTTP statuses. Blocks merges.
2. **Layer 2 (Advisory AI Explorer):** A vision-language exploratory testing agent that simulates real human personas ("nervous first-time student", "invigilator watching 6 candidates") and reports visual hesitation, confusing states, and dead ends. **Advisory only — never blocks merges.**

Two open-source frameworks were evaluated for the Layer 2 exploratory layer:
- **Midscene.js** (`web-infra-dev/midscene`): Vision-Language Model (VLM) UI automation with native Playwright integration (`@midscene/web/playwright`), `ai()`, `aiQuery()`, `aiAssert()`, visual HTML step reports, and prompt plan caching.
- **TesterArmy `e2e`** (`tester-army/e2e`): Natural-language `agent.act()` and `agent.assert()` on top of Playwright, step record-and-replay, multi-engine browser support, with anonymous telemetry.

## 3. Decision

**Adopt Midscene.js (`@midscene/web/playwright`) as ProctorNet's Layer 2 AI Exploratory Testing Engine. Do not retain or dual-maintain TesterArmy `e2e`.**

### Rationale:
1. **Seamless Stack Cohesion:** Midscene attaches directly into `@playwright/test` via `base.extend(PlaywrightAiFixture())`. This allows all custom test fixtures developed in Layer 1 (`e2e/helpers/guard.ts`, `actors.ts`, fake webcam flags, Companion agent child processes) to be shared with zero duplicated harness code.
2. **Visual Inspection Quality:** Midscene's visual HTML reports provide immediate visual feedback of candidate hesitation, confusing button placements, and awkward contrast without human test engineers needing to step through traces.
3. **Structured Extraction (`aiQuery`):** Midscene allows querying the page for structured UX defects via JSON schemas:
   ```ts
   const findings = await aiQuery<{ severity: string; issue: string; suggestion: string }[]>(
     'Identify any confusing wording, dead-end states, or unreadable elements on this screen'
   )
   ```
4. **Privacy & Telemetry:** Midscene respects strict enterprise privacy boundaries with zero third-party telemetry, ensuring full compatibility with self-hosted OpenAI-compatible VLMs (e.g., vLLM with Qwen2-VL or local Ollama).

## 4. Guardrails & Operational Envelope

To prevent model non-determinism from causing false alarms or runaway costs, the following operational guardrails are enforced:
1. **Advisory Status:** AI explorer runs are strictly **advisory**. Findings are written to `reports/ai-tester/<date>/findings.json` and posted as PR review comments. They **never fail `ci-gate`**.
2. **Environment Isolation:** AI exploration runs **only** against staging or local test containers (`http://localhost:5173`). An explicit host guard throws an error if any non-allow-listed domain (e.g., production) is supplied in `E2E_BASE_URL`.
3. **Synthetic Data Exclusively:** All persona profiles and camera video feeds use synthetic fixtures (`e2e/fixtures/faces/*`). No real student data is ever supplied to vision models.
4. **Budget & Cost Caps:** 
   - Per-run token ceiling: maximum 50,000 prompt tokens per run.
   - Temperature set to lowest supported level (`temperature: 0.1`) for reproducible step planning.
   - Caching enabled by default (`MIDSCENE_CACHE=true`) to reuse plans across unchanged pages.
5. **Objective Guard Dual-Run:** Every AI persona scenario runs alongside the Layer 1 `guard.ts` (console/network guard) and `api.ts` (server-state assertion). A hallucinated "everything looks fine" cannot mask an HTTP 500 error or a broken database write.

## 5. Implementation Roadmap

- `e2e/ai/personas/`: Versioned natural language scenarios (`student-enrollment.spec.ts`, `exam-pressure.spec.ts`, `invigilator-monitoring.spec.ts`).
- `e2e/ai/ux-audit.spec.ts`: Page-by-page structured heuristic scan (`aiQuery`) checking for technical jargon leaks and dead ends.
- CI Schedule: Nightly execution and `workflow_dispatch` trigger in `.github/workflows/ci.yml`.
